URL Shortener Project Explanation

1. Overview
This application creates shareable short URLs, redirects visitors to their original destinations, and records click analytics.

2. Architecture
- Frontend: HTML, CSS, and JavaScript served from the public directory.
- Production backend: Cloudflare Pages Functions.
- Local backend: Express, using the same PostgreSQL service logic.
- Database: PostgreSQL. Cloudflare Hyperdrive connects Pages Functions to the database.
- Browser convenience: localStorage remembers the short IDs created in that browser; PostgreSQL remains the source of truth.

3. Data
The schema in schema.sql creates:
- short_urls: short ID, destination URL, click count, and creation time.
- url_visits: one timestamped record per redirect visit.

4. Request flow
1. The browser sends the destination URL to POST /url.
2. The function validates the URL and inserts a unique short ID into PostgreSQL.
3. The browser saves that ID in localStorage and requests the corresponding link list.
4. A visitor opening /:shortId has the visit recorded in PostgreSQL and is redirected to the destination.
5. Analytics are returned by GET /url/analytics/:shortId.

5. Main files
- index.js: local Express server.
- connect.js: PostgreSQL connection handling.
- schema.sql: PostgreSQL schema.
- lib/url-service.js: shared PostgreSQL operations.
- functions/: Cloudflare Pages API and redirect handlers.
- controllers/ and routes/: local Express handlers.
- public/: frontend files.

6. Local development and deployment
Set DATABASE_URL in .env and apply schema.sql before running npm start. For Cloudflare Pages, configure a Hyperdrive binding named HYPERDRIVE using the ID in wrangler.toml, then deploy the public directory with Wrangler.
